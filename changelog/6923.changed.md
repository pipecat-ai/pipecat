- ⚠️ `RTVIClientSerializer` hands every RTVI message from the bot to the pipeline as an `InputTransportMessageFrame`, instead of turning the bot's reports into the client pipeline's own frames (`BotStartedSpeakingFrame`, `InterruptionFrame`, `LLMTextFrame`, `TTSTextFrame`, the function call frames and `TranscriptionFrame`). In the client's pipeline those frames are about its own output. Kept as one kind of frame, the bot's messages also arrive in the order the bot sent them. `RTVIClientTransport` hands them to the pipeline downstream only, so a `PipelineWorker`'s own `RTVIProcessor`, ahead of the pipeline, never takes them for a client's messages. The eval harness maps them to the same scenario events as before.
