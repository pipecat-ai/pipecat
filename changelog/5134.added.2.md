- Added `ErrorCategory`, recording why an operation failed — a rejected API key (`AUTHENTICATION`) versus a provider outage (`SERVER`), for example — so error handlers can tell a transient failure from one that will keep recurring until the configuration changes.

    `ErrorFrame` carries it in a new `category` field, and `FrameProcessor.push_error()` accepts it as an argument:

    ```python
    await self.push_error("rejected API key", category=ErrorCategory.AUTHENTICATION)
    ```

    Every error reaching a handler carries a category; `ErrorCategory.UNKNOWN` means the cause couldn't be determined, which handlers can treat the way they treated every error before.

    A service works the category out from the exception only when the reporter left it unset, and only then does the error count towards the service's health — so an error is never mistaken for a verdict on a service it didn't come from:

    - Failures in application code a service invoked are reported as `ErrorCategory.APPLICATION`. A tool handler or TTS text transformer whose own API call returns 401 leaves the service untouched, since its credentials were never in question.
    - Errors caught by a broad `except`, which may not have come from the service at all, are reported as `ErrorCategory.UNKNOWN`.
