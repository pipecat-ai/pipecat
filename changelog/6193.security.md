- Services for OpenAI-compatible providers no longer send `OPENAI_API_KEY` to their provider when given no `api_key`. The OpenAI client they build on falls back to that variable when given no key, so an application that set it for OpenAI handed its OpenAI key to the other provider, including when an `api_key=os.getenv(...)` read an unset variable. Affects `BasetenLLMService`, `CerebrasLLMService`, `CrusoeLLMService`, `DeepSeekLLMService`, `FireworksLLMService`, `GrokLLMService`, `GroqLLMService`, `GroqSTTService`, `InceptionLLMService`, `MistralLLMService`, `NebiusLLMService`, `NovitaLLMService`, `NvidiaLLMService`, `OpenRouterLLMService`, `PerplexityLLMService`, `QwenLLMService`, `SambaNovaLLMService`, `SarvamLLMService` and `TogetherLLMService`.
