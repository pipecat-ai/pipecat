- Added `pipecat textflow`, a tool that traces a theoretical LLM response through a pipeline's text path without calling an LLM. A `TextFlowSetup` describes what sits downstream of the LLM: the `LLMTextProcessor` and its aggregator and transforms, the TTS service's aggregation, skipped text types and transforms, and the `RTVIObserver`'s output transforms. `pipecat textflow run` prints how the response is cut into segments, what each stage did to every segment, and what reached the conversation context, the RTVI client and the TTS provider; `--steps` lists every step of the run in order, and `--text-file` reads the response from a file. `pipecat textflow serve` opens an interactive page whose flow diagram steps through the run: chunks arriving, aggregator buffers filling and cutting, frames moving between processors, words released by the transport on time, and what the context and the client hold at each step. Pass `--bot bot.py` to either command to trace a bot's own text path instead of a setup: the file is imported, its `bot(runner_args)` builds its pipeline against a stub transport, and the trace runs the bot's `LLMTextProcessor`, TTS text handling and `RTVIObserver` parameters as they are, transforms and filters included. The bot's TTS service runs itself, calling its provider, so that provider's own word timestamps, tokenization and rewriting show up; `--stand-in-tts` keeps the offline stand-in with the bot's text handling. From Python, `pipecat.textflow.run_textflow(setup, text)` returns the trace and `pipecat.textflow.capture_bot(path)` captures a bot.
