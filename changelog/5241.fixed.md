- Fixed `DeepgramSTTService` silently discarding audio during the initial WebSocket handshake, which dropped the speaker's first word or two from the transcript. `_connect()` only launches a background task, so `start()` returned while the handshake was still in flight; audio arriving in that window reached `run_stt()` with `self._connection` still `None` and was discarded. `STTService`'s `_reconnect_audio_buffer` did not cover this because it is gated on `_reconnecting`, which only `_reconnect()` sets. `start()` now waits for the connection to be ready, matching `_do_reconnect()` and `DeepgramFluxSageMakerSTTService._connect()`.

  The loss was deterministic rather than intermittent, and scaled with handshake latency. Against live Deepgram the handshake measured ~510ms, and a speaker talking from the start of the call lost the first two words (`alpha bravo charlie delta ...` transcribed as `charlie delton echo ...`, with the word at the boundary also corrupted). With the fix the same audio transcribes in full.

  A new `start_connect_timeout` parameter (default 5.0 seconds) bounds the wait. If the connection is not ready in time, a warning is logged and start proceeds, leaving the existing reconnect and error-reporting paths to handle it.
