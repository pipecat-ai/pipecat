- Fixed an `LLMSetToolsFrame` carrying provider-native tools, such as `[{"google_search": {}}]`, raising `TypeError`. The frame documents that form, but both stops on its path — the universal aggregators, and the handler sync every speech-to-speech service runs on it — normalized it as though it were a list of standard tools. Provider-native tools carry no handlers and don't belong in the context, so both now pass over them. Note that no service yet reads them off the frame when building its session update, so they don't reach a running session.
