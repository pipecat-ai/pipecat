- Fixed the WebSocket transports hanging the pipeline when a peer stops reading.
  The writes that do not go through the media sender had no bound of their own:
  the `clear` a telephony serializer emits on an interruption, a transport
  message, and a DTMF tone. Each runs while the frame is being handled, so a
  write that never returned parked the transport and the `EndFrame` queued
  behind it never reached the end of the pipeline. Those writes are now bounded
  by the existing `TransportParams.audio_out_write_timeout_secs` (default 10s),
  and exceeding it leaves the transport unusable, as an audio write already did.
