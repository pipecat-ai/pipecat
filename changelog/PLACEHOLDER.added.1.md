- `GeminiLiveLLMService` now honors the `interaction_status` reported on `server_content`. On models that perform background reasoning, `turn_complete` only closes an output chunk: the server may still be thinking or preparing an asynchronous tool call, and more audio or tool calls can follow. While the status is `IN_PROGRESS` the bot turn is held open — `TTSStoppedFrame` and `LLMFullResponseEndFrame` are deferred until the session reports going idle, so the whole exchange arrives as a single assistant turn instead of being split at each chunk. Models that report no status keep the plain `turn_complete` behavior.

  Both spellings of the idle state are accepted — `IDLE`, and its pre-launch name `REQUIRES_ACTION` — so the service works across server builds and `google-genai` versions. If the session never reports going idle, the turn is closed anyway after 30 seconds.

  `interaction_status` reaches the client only on `google-genai` 2.18.0 and later; older versions drop the field before Pipecat sees it. The `google` extra now requires `google-genai>=2.18.0` (except on Python 3.13/Linux, where `vonage-video-connector`'s pydantic pin caps it lower). Running a model that reports the status on an older SDK logs a warning naming the version to upgrade to, rather than silently splitting replies across turns.
