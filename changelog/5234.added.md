- Added a `leading_strip_characters` parameter to `TTSService`, extending the existing leading-whitespace strip at the start of a context to other non-speech characters. Empty by default, so behavior is unchanged unless configured. `CartesiaTTSService` defaults it to the punctuation Cartesia's normalizer discards, since a transcript made only of those normalizes to empty and is rejected — which an LLM can produce by opening a resumed reply with a bare ellipsis.
