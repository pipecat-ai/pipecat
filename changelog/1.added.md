- Enabled MoQ client mode, where the bot and the browser both dial a relay and rendezvous there instead of the bot serving its own socket. Since neither side needs a reachable address, this works when the bot is behind NAT.
  - Select it by naming a relay: `python bot.py -t moq --moq-connect https://cdn.moq.dev/anon`. Without `--moq-connect` the bot serves its own socket, as before.
  - Each client-mode session gets its own random namespace, so concurrent sessions on a shared relay don't collide. Pass `--moq-namespace` to pin a well-known room instead.
- Added `--moq-direct`, which drops the `/start` rendezvous: the runner watches the relay for browsers and gives each one its own bot, so a session begins whenever someone opens the page.
  - The relay rides in the client URL (printed at startup) instead of a `/start` response, so nothing has to reach the runner over HTTP to bring a bot up.
  - Each browser mints a session id and publishes under `<client-id>/<id>`. The runner watches that prefix and starts a bot per id, publishing the matching `<bot-id>/<id>` back, so several people can share one URL and still get their own call.
  - Calls sit at the relay root by default, since the session id is what separates callers. `--moq-namespace` scopes them to a room instead, and the bot then ignores traffic elsewhere on the relay — worth setting on a shared relay, where anything announced at the root will otherwise start a bot.
  - Client mode only — serve mode's browser needs the self-signed cert fingerprint that only `/start` carries.
- Added `MOQRunnerArguments.connection_timeout`, overriding `MOQParams.connection_timeout` for a session. Direct mode raises it: the stock value assumes a bot spawned as a client connects, but a direct-mode bot reaches the relay first and waits for someone to open the page.
- Added `MOQParams.response_path` and `MOQParams.request_path`, which set the bot's broadcast paths directly (the bot publishes its `response_path`, subscribes to the peer's `request_path`) instead of deriving them from `namespace` + `participant_id` / `peer_id`.
  - The namespace layer needs both peers to agree on a namespace up front. These are for deployments where the paths are assigned externally instead — e.g. a relay that routes on a path prefix and derives the bot's path from the peer's, so there's no namespace to agree on.
  - Either can be set alone; the other still derives from the namespace. Unset, behaviour is unchanged.
- The default participant ids are now named by direction: the bot publishes under `<namespace>/response` and subscribes to the peer at `<namespace>/request` (previously `bot0` / `client0`). `--moq-bot-id` / `--moq-client-id` still override them.
