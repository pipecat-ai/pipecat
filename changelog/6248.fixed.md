- Fixed `DeepgramFluxTTSService` staying usable when Deepgram refuses its connection for a setting it won't accept (such as an out-of-range `expressivity`) or a bad API key. The service retried the same connection on every bot reply, so the bot went silent and a configured failover never took over. Such a refusal now makes the service unusable, as it already did for `DeepgramTTSService`; a rate limit (429) or a server error (5xx) is still retried.
