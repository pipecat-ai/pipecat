- Fixed TTS text that was never rendered as audio being written to the LLM context. When a websocket TTS connection dies with the socket still open (e.g. a keepalive-timeout kill), `run_tts()` returns cleanly but no audio ever arrives; the audio context drains via the stop-frame timeout and force-complete emits the un-rendered remainder, which was stamped `append_to_context=True` and entered the conversation history as something the bot said — so every later turn reasoned from a question the user never heard. A context that produced no audio at all now stamps its force-completed remainder `append_to_context=False` and logs a warning. Contexts that rendered any audio keep the existing behavior, since dropped word-timestamp events with fully played audio are indistinguishable from a stream dying mid-utterance at this layer.
