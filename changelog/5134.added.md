- Added `AIService.status`, reporting a service's health as a `ServiceStatus` (`UNKNOWN`, `READY`, `DEGRADED`, `UNAVAILABLE` or `MISCONFIGURED`) so applications can tell a service that's briefly struggling from one that will never work until it's reconfigured.

    `ServiceStatus.is_usable` answers whether the service is still worth sending work to — true for everything but `MISCONFIGURED`, since a degraded or temporarily unavailable service may start working again on its own. Every service derives its status from the errors it reports; providers that signal failures through SDK-specific exceptions, or whose credentials can be rejected for reasons a reconnection would clear, refine that by overriding `_classify_error()`:

    ```python
    class MyService(TTSService):
        def _classify_error(self, exception: Exception) -> ErrorCategory | None:
            if isinstance(exception, MyProviderAuthError):
                return ErrorCategory.AUTHENTICATION
            return None
    ```

    Status changes are reported through a new `on_status_changed` event handler, which fires on the transition rather than on every error:

    ```python
    @service.event_handler("on_status_changed")
    async def on_status_changed(service, previous, current):
        if not current.is_usable:
            logger.error(f"{service} needs attention: {current.value}")
    ```

    A misconfigured service gets another chance whenever its settings change, since new credentials or a new model name may be exactly what fixes it.
