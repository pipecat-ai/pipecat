- Fixed `SarvamTTSService`, `SarvamHttpTTSService`, `SarvamSTTService` and `SarvamHttpSTTService` silently ignoring a setting passed as a constructor argument, such as `voice="anushka"` or `language="hi-IN"`, and using the default instead. They now raise a `TypeError` that points to `settings=<Service>.Settings(...)`, as `SarvamRealtimeSTTService` already did. Sarvam's own names for these settings, `speaker` and `target_language_code` on the TTS services, are rejected the same way, with a message naming the field to use, such as `Settings(voice=...)`.
