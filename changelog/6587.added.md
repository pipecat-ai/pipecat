- Added "user waiting" beside "user idle": the same silence after the bot's turn, told apart by whether background work is in progress.
  - `BackgroundWorkStartedFrame` and `BackgroundWorkFinishedFrame`, broadcast to bookend background work that doesn't block the conversation. `LLMService` broadcasts them around an asynchronous function call (`cancel_on_interruption=False`), and `BackendConnector` around the work an `LLMWithBackend` backend has in flight. A component that dispatches other such work, like a job to another worker, should broadcast the same pair, keyed by `work_id`.
  - `user_waiting_timeout` on `LLMUserAggregatorParams` and `UserTurnProcessor`, with the `on_user_waiting` event: how long the conversation stays quiet, with background work in progress, before the user counts as waiting. 0, the default, turns it off.
  - `UserTurnIdleFrame` and `UserWaitingFrame`, broadcast with the `on_user_turn_idle` and `on_user_waiting` events, so a processor can act on either silence. Each carries `quiet_secs`, how long nothing has been said.
  - `UserWaitingTimeoutUpdateFrame`, which sets the waiting timeout at runtime the way `UserIdleTimeoutUpdateFrame` sets the idle one.
  - An `LLMMarkerResponseFrame` of kind `silent`, reporting a reply the LLM left unspoken, starts the idle or waiting timer over the way the bot speaking does, so the next interval gets a fresh decision.
