- Added `FlowConfig`, which describes a Pipecat Flows conversation as data so a bot can load its flow at runtime. A config names the initial node and, for each node, its messages, the tools it offers, and where each tool leads. Load it with `FlowConfig.from_file()` or `from_yaml()`, then `bind()` it to the module holding your direct functions and hand the result to `FlowManager`.

  Tools stay in Python and return `(result, None)`; the config picks the next node, by name or with a branch table keyed on a field of the result. `bind(variables=...)` fills `{{ variable }}` placeholders in messages, and YAML configs can `!include` sibling files. The format's JSON Schema ships as `pipecat/flows/flow_config.schema.json`.

  ```yaml
  initial_node: greet
  nodes:
    greet:
      role_message: You take food orders for {{ restaurant_name }}.
      task_messages:
        - role: developer
          content: Greet the caller and ask: pizza or sushi?
      functions:
        - name: choose_pizza
          transition_to: pizza
    pizza:
      task_messages:
        - role: developer
          content: Take the pizza order.
      functions:
        - name: select_pizza_order
          transition_to:
            field: status
            cases: { ok: confirm, unavailable: pizza }
  ```

  ```python
  import tools  # direct functions: choose_pizza, select_pizza_order, ...

  config = FlowConfig.from_file("flow.yaml")
  flow = config.bind(tools=tools, variables={"restaurant_name": "Luigi's"})
  flow_manager = FlowManager(
      worker=worker,
      llm=llm,
      context_aggregator=context_aggregator,
      global_functions=flow.global_functions,
  )
  await flow_manager.initialize(flow.initial_node)
  ```

  `examples/flows/food_ordering_yaml.py` is the food-ordering example built this way.
