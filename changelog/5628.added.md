- Added `FlowConfig`, which describes a Pipecat Flows conversation as data so a bot can load its flow at runtime. A config names the initial node and, for each node, its messages, the tools it offers, and where each tool leads. Load it with `FlowConfig.from_file()` or `from_yaml()`, construct a `Flow` from it and the module holding your direct functions, and hand that to `FlowManager`.

  Tools stay in Python and return `(result, TRANSITION_IN_YAML)`; the config picks the next node, by name or with a branch table keyed on a field of the result, where case keys may be strings, booleans, or numbers. An entry marked `transition_to: TRANSITION_IN_PYTHON` lets its tool return `(result, "<node name>")` instead, choosing among the config's nodes in code. `Flow(..., variables=...)` fills `{{ variable }}` placeholders in messages, and YAML configs can `!include` sibling files. The format's JSON Schema ships as `pipecat/flows/flow_config.schema.json`. Constructing the `Flow` reports every tool, handler, or variable the config names but cannot resolve, together, as a `FlowReferenceError`. `Flow(..., variables=...)` fills `{{ variable }}` placeholders in messages, and YAML configs can `!include` sibling files. The format's JSON Schema ships as `pipecat/flows/flow_config.schema.json`.

  ```yaml
  initial_node: greet
  nodes:
    greet:
      role_message: You take food orders for {{ restaurant_name }}.
      task_messages:
        - role: developer
          content: Greet the caller and ask: pizza or sushi?
      functions:
        - name: choose_pizza
          transition_to: pizza
    pizza:
      task_messages:
        - role: developer
          content: Take the pizza order.
      functions:
        - name: select_pizza_order
          transition_to:
            field: status
            cases:
              ok: confirm
              unavailable: pizza
  ```

  ```python
  import tools  # direct functions: choose_pizza, select_pizza_order, ...

  config = FlowConfig.from_file("flow.yaml")
  flow = Flow(config, tools=tools, variables={"restaurant_name": "Luigi's"})
  flow_manager = FlowManager(
      worker=worker,
      llm=llm,
      context_aggregator=context_aggregator,
      global_functions=flow.global_functions,
  )
  await flow_manager.initialize(flow.initial_node)
  ```

  Five of the flows examples have YAML twins beside their Python versions: `hello_world_yaml.py`, `food_ordering_yaml.py`, `restaurant_reservation_yaml.py` (which routes on the availability check's result), `patient_intake_yaml.py` (which fills names in from variables), and `podcast_interview_yaml.py`.
