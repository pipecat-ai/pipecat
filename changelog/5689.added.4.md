- Speech-to-speech LLM services now take messages appended to the conversation (`LLMMessagesAppendFrame`) into their session, each on whatever second channel its provider offers: OpenAI Realtime, Azure Realtime and Grok as conversation items, Gemini Live as client content that does not complete the turn, Nova Sonic as a text event. Whether the model answers them is the assistant aggregator's call, as for a tool result: an append that asks to run comes back as the context frame the aggregator pushes upstream, which creates the response, so the hold while the bot speaks and the bundling of a burst apply. This is what carries a backend's messages to a speech-to-speech frontend of an `LLMWithBackend`.
- Speech-to-speech LLM services now deliver a tool's intermediate results (reported with `FunctionCallResultProperties(is_final=False)`) to their model, each on whatever second channel its provider offers, since a function call itself takes one output: OpenAI Realtime, Azure Realtime and Grok put them in as conversation items, Gemini Live as a `will_continue` tool response, Nova Sonic as a text event and Ultravox as user-side text. The result's `run_llm` says whether the model should answer it or just take it in. A service that can't do this says so with `LLMService.accepts_intermediate_function_call_results` — Inworld Realtime, whose model calls the tool again rather than relaying what it was told — and drops intermediate results with a warning.
