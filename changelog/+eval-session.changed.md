- `EvalSession.from_scenario()` builds the session for a loaded scenario of either kind, an `EvalScriptSession` for a scripted scenario or an `EvalSimulationSession` for a simulation, and `EvalSession` is the base class of both. Constructing `EvalSession(...)` directly is no longer supported; use the kind's own class.
- The eval sessions, `EvalSuite.run()`, and `EvalClient` take how a run behaves as one `EvalSessionParams` (`connect_timeout_s`, `default_timeout_ms`, `record_path`, `cache_dir`, `use_cache`, `stop_bot`, `trigger_disconnect`) instead of separate keyword arguments, and the services a run uses (`judge`, `user_tts`, `bot_stt`, and a simulation's `persona_llm`) as keyword arguments on both `from_scenario()` and the constructors. `EvalClientParams` now holds only what the scenario asks of the bot.
