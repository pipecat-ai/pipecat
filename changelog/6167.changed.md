- `PipelineWorker` now pushes the `StartFrame` while processors are still being set up, and each processor holds it only until its own `setup()` is done. A slow connection (e.g. the LLM's) no longer delays processors ahead of it: the input transport starts reading audio right away and STT gets it as soon as its own connection is up. `on_pipeline_started` still fires when the `StartFrame` reaches the end of the pipeline, after every processor has been set up and has handled it. `start_timeout_secs` now counts from when every processor is set up. The input transport's `on_client_connected` can now fire before later services have connected; use `on_pipeline_started` for anything that needs them.
