- `OpenAIResponsesLLMService` (WebSocket) now runs each request on a `stream_id` lane and, when a response is interrupted, leaves it to finish on its lane while the next request starts at once on a fresh one, dropping the abandoned response's events by their tag. The turn after an interruption no longer waits for the abandoned reply to drain, reconnects, or fails a `previous_response_id` chain first, and an abandoned reply can no longer be delivered as the next turn's answer. A server that does not tag its events keeps a drain, now bounded to one second before the connection is replaced, and a server that rejects `stream_id` is sent plain requests. The undocumented `response.cancel` message is no longer sent.
