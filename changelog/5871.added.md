- `BaseUIWorker` now owns the screen: the client's latest snapshot, `@ui_event` dispatch, and the commands that drive the page (`send_command`, `click`, `scroll_to` and the rest). It takes an optional `classifier` and asks it the small questions about the screen without an LLM: `should_respond(event)` says whether a UI event calls for the assistant to speak, and `which_element(description)` picks the element the user means from the snapshot. A bot whose screen work is picking and acting can use `BaseUIWorker` directly and let its voice LLM do the talking. `UIWorker` still adds the LLM turn on top and is unchanged for its users.

  ```python
  class ScreenWorker(BaseUIWorker):
      @ui_event("nav_click")
      async def on_nav(self, message):
          if await self.should_respond(message):
              ...


  screen = ScreenWorker("screen", classifier=JevClassifier(api_key=...))
  ref = await screen.which_element("the blue button")
  await screen.click(ref)
  ```
