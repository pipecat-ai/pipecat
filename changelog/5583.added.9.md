- The development runner serves SIP bots: `-t sip` starts the HTTP server with
  `POST /start` (transport `sip`, the account in `body.sip_client`) and
  `POST /daily-sip-trunk-webhook`, a local stand-in for Pipecat Cloud's handler
  of Daily SIP-trunk notifications, which starts a bot on the per-call SIP
  client each notification carries. `-t sip -d` runs one bot immediately with
  no server, as `-t sip` did before. `create_transport()` builds the SIP
  transport from plain runner arguments whose body carries `sip_client` or
  whose environment holds the account, so a bot writes the same line under the
  runner and on Pipecat Cloud. `pipecat.runner.sip.configure()` reads the
  account and its transport from a request body before the environment, and
  `pipecat.runner.sip.sip_runner_arguments()` is the public conversion from an
  account to `SIPRunnerArguments`.
