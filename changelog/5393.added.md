- Added `max_consecutive_zero_audio_contexts` to `TTSService`. A provider can accept every request and answer with silence — an unknown voice ID, say — without ever reporting an error, leaving the bot mute with nothing in the logs to explain it. Every TTS context that completes without producing audio reports an error the service can carry on from, so application code hears about a turn that produced no speech as it happens. After this many silent contexts in a row, the service reports a permanent error instead, stops being given work, and the pipeline worker applies its `ProcessorUnusablePolicy` (a `ServiceSwitcher` fails over to another provider). Defaults to 3; set it to 0 to report silent contexts without ever writing the service off.
