- Fixed `BaseOutputTransport` interruptions discarding output work that should survive them:
  - An uninterruptible frame the output was already handling, such as an action awaited in `write_transport_frame()` or the EndFrame's trailing silence, was cancelled mid-flight. It now finishes, and only the interruptible frames queued behind it are dropped.
  - An interruption arriving after the EndFrame reached the output transport, for example the user talking over the bot's goodbye, dropped that EndFrame, so the pipeline never finished.
