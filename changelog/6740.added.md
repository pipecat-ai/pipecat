- Added `EvalRubric` (`pipecat.evals.simulation`) to judge a conversation the eval harness didn't drive, such as a production call recorded by `EvalConversationObserver`. A rubric holds a simulation's judging keys, `judge`, `success` and judged `metrics`, with no persona or goal, and `EvalSimulationJudge` takes one wherever it takes a simulation. In a scenario file, an entry with `success:` and neither `persona:` nor `turns:` is a rubric: `EvalScenarioFile.load()` returns it with the file's defaults merged in, `pipecat eval run` and `pipecat eval suite` skip it, since it has nothing to run, and `pipecat eval judge -s <entry>` judges saved conversations with it. `EvalRubric.from_dict()` builds one from a mapping with the same keys. A measured metric needs a live run, so a rubric leaves out the ones it takes from the file's `metrics:` and refuses one it lists itself.

  ```yaml
  name: food_ordering
  judge: !include judge_text.yaml
  scenarios:
    - name: production
      success: "the bot took the caller's order and completed it"
      metrics:
        - name: politeness
          criterion: "the reply is courteous and helpful, never curt or dismissive"
          min_score: 1
  ```

  ```python
  rubric = EvalScenarioFile.load("food_ordering.yaml")["food_ordering/production"]
  judgement = await EvalSimulationJudge(rubric).judge(message.conversation)
  ```
