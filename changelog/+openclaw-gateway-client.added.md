- Added OpenClaw Gateway support in `pipecat.services.openclaw`. The OpenClaw Gateway is the websocket an OpenClaw agent publishes for other programs to drive it, and a NemoClaw sandbox republishes it on the host, so a bot outside the sandbox can run an agent inside one.

  `OpenClawGatewayClient` speaks the protocol: it starts a run with `chat.send`, streams its output as `OpenClawEvent`s, redirects work already in flight with `sessions.steer`, and stops it with `chat.abort`. It builds on `WebsocketService`, so a failed socket reconnects with exponential backoff and connection errors are reported through an `on_connection_error` event handler. One connection serves every run: aborting has to work after a run's event stream has ended, and a request written to a socket whose reader has stopped never gets a reply. A run cannot survive a dropped connection, since the Gateway cannot resume a run's event stream, so runs in flight end with a `failed` event rather than leaving a caller waiting.

  `OpenClawGatewayProcessor` is the pipeline half. `OpenClawSendFrame` starts a run, `OpenClawSteerFrame` redirects the one in flight, and `OpenClawAbortFrame` stops it; what the Gateway streams back arrives as `OpenClawTextFrame` between an `OpenClawRunStartedFrame` and one terminal frame. An agent run is not a spoken turn, so the processor reads and writes no conversational frames — what an agent's output should sound like belongs to a service wrapping it.

  Two Gateway behaviors are worth knowing before using it. `sessions.steer` does not inject into the running turn; it aborts that run and starts a new one carrying the follow-up, and the client moves the run onto the replacement so the stream follows it. `chat.abort` answers `aborted: false` for both a finished run and an unknown one, so `False` means there was nothing to stop rather than that something failed.
